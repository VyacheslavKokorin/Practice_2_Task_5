# Дневник путешествий

Простой сайт, на котором пользователи могут создавать записи о путешествиях и смотреть записи других людей.

## Возможности

- регистрация и вход в аккаунт;
- создание путешествия;
- просмотр своих и чужих путешествий;
- добавление геопозиции;
- добавление изображения по ссылке;
- указание стоимости путешествия.

## Технологии

- Node.js 24;
- Express;
- SQLite;
- HTML и CSS.

## Запуск

```powershell
git clone https://github.com/VyacheslavKokorin/Practice_2_Task_5.git
cd Practice_2_Task_5
Copy-Item .env_example .env
cd app
npm install
npm start
```

После запуска сайт будет доступен по адресу: http://localhost:3000

## База данных

В базе данных используются две таблицы:

- `users` — пользователи сайта;
- `trips` — записи о путешествиях.

Каждое путешествие связано с пользователем через поле `user_id`.

## Анализ выполненной задачи

1. Сначала я разобрал требования и выбрал простой стек на Node.js, Express и SQLite. Для такого небольшого проекта этих технологий достаточно.
2. Я создал таблицы пользователей и путешествий. Связь между ними позволяет определить автора каждой записи.
3. Для пользователей сделана регистрация. Пароли хранятся в виде хеша, а не обычного текста.
4. Я добавил вход, выход и сессии. Страницы создания и просмотра своих путешествий закрыты от гостей.
5. Пользователь может заполнить форму и сохранить путешествие. Запись получает название, место, описание, даты и автора.
6. На главной странице выводятся путешествия всех пользователей. В отдельном разделе показываются только записи текущего пользователя.
7. Для путешествий добавлены три дополнительные функции: геопозиция, изображение и стоимость. Координаты можно открыть на карте OpenStreetMap.
8. Введённые данные проверяются на сервере. Также пользовательский текст экранируется перед выводом на страницу.
9. Для всех страниц сделано общее простое оформление. Сайт можно использовать на компьютере и на небольшом экране.

## Выявленные ошибки и рекомендации

1. При запуске командой `node start` приложение не работает. Нужно использовать команду `npm start`.
2. Без файла `.env` сервер не запускается. Перед запуском нужно создать `.env` копированием файла `.env_example`.
3. В форме можно было указать дату окончания раньше даты начала. Для таких данных нужна проверка в приложении и в базе данных.
4. Начальные данные могли добавляться повторно. Для тестового путешествия добавлена проверка, которая не допускает дубликаты.
5. Изображение загружается по внешней ссылке и со временем может стать недоступным. В дальнейшем можно добавить загрузку файлов на сервер.
6. Координаты вводятся вручную. В дальнейшем можно добавить выбор точки прямо на карте.
7. Текущие сессии подходят для учебного проекта. Для публикации сайта лучше хранить сессии в отдельной базе данных.
